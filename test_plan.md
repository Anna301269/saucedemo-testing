# Тест-план: SauceDemo (www.saucedemo.com)

## *Введение*
### Цель тестирования
Проект выполняется как учебный (pet-проект) для отработки навыков ручного функционального тестирования.

### Тестируемое приложение
* Название: SauceDemo
* URL: https://www.saucedemo.com/
* Тип: Демо интернет-магазин (учебное приложение)
* Назначение: веб-приложение специально создано с багами для тренировки тестировщиков; поведение может отличаться в зависимости от того, под
каким пользователем выполнен вход.

## *Объем тестирования*
### Что тестируем

* Авторизация и её граничные случаи (разные типы пользователей, неверные
данные, пустые поля, заблокированный пользователь)
* Каталог товаров: отображение, сортировка, фильтрация
* Карточка товара
* Корзина: добавление, удаление, изменение состава
* Оформление заказа (Checkout): ввод данных, шаги оформления, подтверждение
* Навигация: боковое меню, logout, переходы между страницами

### Что НЕ тестируем

* Пользователей performance_glitch_user и visual_user
* Нагрузочное тестирование
* Тестирование безопасности (пентест, SQL-инъекции и т.п.)
* Тестирование на мобильных устройствах и адаптивность
* Кроссбраузерное тестирование (тестируем только в одном браузере)
* Тестирование API 

### Тестовое окружение
Браузер: Яндекс Браузер

ОС: Windows 10

### Тестовые данные
Общий пароль: secret_sauce

| Логин| Комментарий|
|-------|--------|
| standard_user | Базовый пользователь без ограничений |
| locked_out_user | Пользователь, вход для которого заблокирован |
| problem_user | Пользователь с нестандартным поведением UI |
| performance_glitch_user | Пользователь с замедленной работой приложения |
| error_user | Пользователь с нестандартным поведением UI |
| visual_user | Пользователь с нестандартным поведением UI |

### Виды и уровни тестирования
* Функциональное тестирование — соответствие функционала ожидаемому поведению
* UI-тестирование — визуальное отображение элементов
* Негативное тестирование — некорректный ввод, граничные значения
* Smoke-тестирование — базовая проверка ключевых сценариев перед
началом детального тестирования

### Подход к тестированию
* Smoke-тестирование основных сценариев (вход, добавление товара в
корзину, оформление заказа) под standard_user
* Детальное тестирование каждого модуля по подготовленным тест-кейсам
* Повторение ключевых сценариев под остальными типами пользователей
* Регистрация и оформление найденных дефектов
* Составление итогового отчёта
